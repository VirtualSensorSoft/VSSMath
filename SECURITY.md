# Security reporting

Do not report a suspected vulnerability in a public issue. If GitHub private
vulnerability reporting is enabled for this repository, use that channel. If
it is unavailable, contact the organization through its GitHub profile and
request a private reporting route. Do not include secrets or sensitive data in
a public pull request.

The library is a numerical component, not a sandbox or a security boundary.
Callers remain responsible for validating domain-specific inputs and protecting
the process and data in which the library runs.
